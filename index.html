      From a crew of agents to a self-running mesh

      v1 set out 32 agents in 7 divisions around one orchestrator. v2 turns that into a network. Agents send each other typed messages, settle routine decisions among themselves, and every capability is a versioned block you can add, swap or roll back.

      Nine layers, one nervous system

      Events flow down through the layers and decisions flow back up. Only the connector layer can touch the outside world, and it only accepts actions that carry a valid policy verdict and, where required, a signed human approval.

      Framework alignment. The structure follows the enterprise agentic pattern (reimagine, build, empower, orchestrate) and balances speed, scale and trust. Orchestration is graph-based, policies are code, and every decision is explainable and auditable. It's sized for an agency, not a bank.

      How agents talk and decide

      Agents never call each other directly. They publish typed messages to the Agent Bus, which checks each message against a contract and a talk-permission list. Every decision falls into one of five modes, so the routine ones never wait for a human.

      People-data rules

      • Personal data stays in the People schema with row-level security. Agents outside the division only see names, roles, skills and availability.
      • Pay, rates and bank details are never sent to a model. The Pay Prep agent works with IDs and totals, and a human releases the payment.
      • Transfers of personal data across borders need a lawful mechanism, such as UK IDTA or EU SCCs. Confirm these with your adviser.
      • Employment status, right to work and local labour law vary by country. Agents flag deadlines and missing documents but never decide status.
      • Offboarding revokes every connector token and shared drive within one hour, logged by the Access Steward.

      General guidance, not legal advice.

      Less human input, by earning it

      v2 runs on management by exception. Agents start one level below their target and get promoted on evidence: how often their drafts are approved unchanged, eval scores and incident count. You see exceptions, money and first-time public actions. The routine runs without you.

      Controls the model can't talk its way past

      Safety is enforced in code at the boundary of each tool call, not by prompt discipline. A connector only accepts a write action that carries a signed approval token, and the agent process can never mint that token.

      worker/hooks/preToolUse.ts (illustrative)
      export async function preToolUse(ctx, tool, input) {
  if (await killSwitch.isOn(ctx.agentId)) return deny("paused");
  if (await budget.exceeded(ctx.agentId, ctx.tenant)) return deny("budget");
  const cap = registry.capability(tool.name);           // from connector manifest
  if (!ctx.granted.includes(cap.id)) return deny("not granted");
  if (cap.mode === "write") {
    const ok = await tokenService.verify(input.approval_token, { // separate process
      job: ctx.jobId, action: cap.id, payloadHash: hash(input) });
    if (!ok) return deny("no valid approval token");
  }
  await audit.write(ctx, tool.name, redact(input));
  return allow();
}
